3.1 The C++ ABI Mirage

The Purple Dragon Book (2006) treats calling conventions and vtables as backend code-generation details. In real-world C++ systems, however, the ABI is the architecture. Because C++ encodes template arguments, inline destructors, exception tables, and std::string layouts into mangled symbol names, linking against a subsystem like Blink, Viz, Mojo, or V8 forces every caller to #include the subsystem's entire internal header universe.

Break that coupling once by deleting C++ headers at the boundary, and you never break binary callers again.

3.2 The Two-Header Rule: <stddef.h> and <stdint.h> Only

Every B8G-ABI boundary header obeys one unforgiving rule: it may include only <stddef.h> and <stdint.h>. Zero STL. Zero v8.h. Zero absl. Zero Oilpan. Zero skia.

All data crossing the boundary uses fixed-width, cache-friendly POD structs (B8gFlatFlexItem32C at 32 bytes, B8gVizQuad48C at 48 bytes), and all behavior is exposed through flat C11 function-pointer tables:

#include <stddef.h>
#include <stdint.h>

#define B8G_CHROMIUM_ABI_MAGIC      0x41473842u /* "B8GA" */
#define B8G_CHROMIUM_ABI_VERSION_V2 0x00020000u
#define B8G_CHROMIUM_ABI_VERSION_V3 0x00030000u

typedef struct B8gChromiumAbiTable {
  uint32_t magic;
  uint32_t abi_version;
  const B8gIpczDispatchTable*      ipcz;
  const B8gBlinkFlexDispatchTable* blink_flex;
  const B8gVizDispatchTable*       viz;
  const B8gV8DispatchTable*        v8;
  const B8gBaseDispatchTable*      base;
  const B8gMojoDispatchTable*      mojo;
  const B8gNetDispatchTable*       net;
  const B8gGpuDispatchTable*       gpu;
  const B8gShellDispatchTable*     shell;
} B8gChromiumAbiTable;

Because downstream consumers parse ~190 lines of pure C11 instead of 500,000 lines of C++ templates, each subsystem wrapper compiles in 170 ms (and zero-v8.h C-ABI consumers compile in 90.52 ms), producing 18 real Chromium subsystem DLLs ranging from 11.5 KB to 13 KB each — a > 10,000× reduction compared to the 166.41 MB chrome.dll monolith.

3.3 Step-Wise v2 → v3 Prefix Compatibility (offsetof == 0)

A common objection to flat C function tables is evolution: how do you add new subsystems without a flag-day rebuild?

B8G-ABI v3 solves this with monotonic prefix embedding verified at compile time (_Static_assert(offsetof(B8gChromiumAbiTableV3, v2) == 0)):

typedef struct B8gChromiumAbiTableV3 {
  B8gChromiumAbiTable v2; /* MUST stay at byte offset 0 */
  uint32_t struct_size;   /* sizeof(B8gChromiumAbiTableV3) */
  uint32_t capability_flags;
  const B8gOriginArenaDispatchTable* origin_arena;
  const B8gCloudSyncV3DispatchTable* cloud_sync;
  const B8gLibNodeDispatchTable*     libnode;
  const B8gAbiUpgradeDispatchTable*  upgrade;
} B8gChromiumAbiTableV3;

static inline int b8g_abi_is_v3(const B8gChromiumAbiTable* tbl) {
  if (!tbl || tbl->magic != B8G_CHROMIUM_ABI_MAGIC) return 0;
  if (tbl->abi_version < B8G_CHROMIUM_ABI_VERSION_V3) return 0;
  const B8gChromiumAbiTableV3* v3 = (const B8gChromiumAbiTableV3*)tbl;
  return v3->struct_size >= sizeof(B8gChromiumAbiTableV3);
}

Bidirectional Compatibility Invariants

  • v2 Host + v3 Module: Reads the exact offset-0 v2 prefix; safely ignores the appended v3 tail.
  • v3 Host + v2 Module: b8g_abi_is_v3() returns 0; host stays in v2 compatibility mode with zero crashes.
  • v3 Host + v3 Module: Verifies struct_size and capability_flags (B8G_CAP_ORIGIN_ARENA, B8G_CAP_CLOUD_SYNC, B8G_CAP_LIBNODE_SHARED_V8) and enables live RAM hot_swap_subsystem() without touching chrome.dll or v8.dll.
